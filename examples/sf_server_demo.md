## 1. Architecture: Phenix here, GPU somewhere else

Phenix keeps a **cctbx-feel** handle (`StructureFactorServer`). Structure factors and parameter derivatives run on a **torch worker**, which can live on **another machine** (a GPU server). Redis is the only coupling — the Phenix process does not import torch and does not need CUDA.

```bash
# On the GPU server (often a different host):
redis-server
phridge-worker --redis-url redis://0.0.0.0:6379/0 --device cuda

# On the Phenix workstation:
from phridge.client import StructureFactorServer
sf = StructureFactorServer("redis://gpu-lab.example.edu:6379/0")
```

This demo uses `StructureFactorServer(memory=True)` so it runs without `redis-server`. Swap in the Redis URL above for a real remote GPU box.

## 5. Production checklist

1. Start Redis + `phridge-worker --device cuda` **on the GPU host**.
2. On Phenix, `StructureFactorServer("redis://<gpu-host>:6379/0")`.
3. Call `.f_calc` / `.gradients` / `.target_and_gradients` as if they were local cctbx.
4. Keep torch off the Phenix process; keep cctbx off the GPU worker.
