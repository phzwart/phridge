## Setup

This example is a **torch-native workflow** that still gets geometry restraint energy, Cartesian gradients, and Phenix-style statistics from **CCTBX** — without importing cctbx in the driver or evaluating a torch copy of the restraint residual. phridge is the glue: packed sites go out, `E` / `∂E/∂x` / stats come back, and torch autograd only sees the decoder VJP.

Torch owns Adam on a **fixed invertible** per-residue encoder (15-D ALA coords ↔ 64-D). CCTBX owns a live GRM behind ``restraints_handle`` and evaluates ``energies_sites``. Every science hop is ``Bridge.call`` (same protocol as Redis + ``phridge-cctbx-worker``).

```python
built = RemoteRestraintBuilder(bridge).build(pdb_string=pdb)
geo = RemoteGeometry.from_build(bridge, built)
z = encoder.encode_sites(xyz_scrambled, slices).detach().requires_grad_(True)
opt = torch.optim.Adam([z], lr=...)
for _ in range(steps):
    xyz = encoder.decode_sites(z, ...)
    E, g_x = geo.energy_and_gradients(xyz.detach().numpy())  # CCTBX via phridge
    (encoder.decode_sites(z, ...) * g_x_t).sum().backward()
    opt.step(); opt.zero_grad()
# geo.last_target["stats"]  → residual sums + RMS deviations
```
